==========================
WHY DO WE NEED THESE IDs?
==========================

USB is more than a low level protocol for data transport. It also defines a
common set of requests which must be understood by all devices. As part of
these requests, the specification defines data structures, the USB
Descriptors, which describe the properties of the device.

This allows the operating system to find out basic properties of a device,
such as the manufacturer and the name of the device, without a
device-specific driver. This is essential, because the operating system
chooses the driver to load based on this information (Plug-And-Play).

Among the most important properties in the Device Descriptor are the USB
Vendor-ID and Product-ID. Both are 16 bit integers. The simplest form of
driver matching is based on these IDs: The driver announces the Vendor- and
Product-IDs of the devices it can handle, and the operating system loads the
appropriate driver when the device is connected.

Obviously, this only works if the pair of Vendor- and Product-ID is unique:
Only devices which require the same driver can have the same pair of IDs.


=====================================================
HOW DOES THE USB STANDARD ENSURE THAT IDs ARE UNIQUE?
=====================================================

The USB Implementers Forum, Inc. (usb.org) needs a legal means to enforce
unique IDs. But the law does not forbid building a device with arbitrary
identifiers, and nobody can hold legal rights in numbers like 233 or 1756.

To gain control over the identifiers anyway, usb.org has registered the
trademark "USB" and its logo. You can obtain a license for the trademark by
agreeing to the terms and conditions of a license agreement. One of these
terms concerns identifiers: It defines usb.org as the sole authority which
assigns USB Vendor-IDs.


==========================================
HOW DO I GET USB IDs FOR MY HOBBY PROJECT?
==========================================

There are two aspects to this question: a legal one and a technical one.

The legal aspect: If you want to sell a product and claim that it complies
with the USB standard, or if you want to put the USB logo on its box, you
must comply with all terms of the USB trademark license agreement. This
involves the payment of considerable fees, which is not practical for hobby
projects. However, if you don't use the USB trademark, you are not bound by
its license agreement.

The technical aspect: All you need is a pair of Vendor- and Product-ID which
is unique on your host computer. There are two kinds of conflicts you want to
avoid:

  - Conflicts with the few devices which are actually connected to your
    computer.
  - Conflicts with the many ID pairs which your operating system knows for
    choosing a driver.

A random Vendor-ID is not a good choice: Vendor-IDs which are unassigned
today will probably be assigned in the future.

A known Vendor-ID with an unused range of Product-IDs is better. Linux and
many other systems use the public USB ID database at
http://www.linux-usb.org/usb.ids to name devices. As of November 2026, this
database lists no products under Vendor-ID 8352 (0x20a0) with Product-IDs
from 17408 (0x4400) to 32767 (0x7fff). If you choose a random Product-ID from
this range, a conflict with a known device is unlikely. You can check the
current state of the database yourself before you choose.

The shared ID pairs listed in the file USB-IDs-for-free.txt are an
alternative, see below.

Please note that this is technical information on how to avoid conflicts,
not legal advice. We cannot guarantee that any of these IDs are free of
conflicts, and we accept no liability.


===========================================
DOES OBJECTIVE DEVELOPMENT ASSIGN USB IDs?
===========================================

No. Objective Development is not authorized by usb.org to assign USB
Vendor- or Product-IDs.


============================
WHAT ABOUT SHARED ID PAIRS?
============================

The examples in this package use a few ID pairs which have been shared by a
large number of V-USB based devices for many years. They are not assigned to
you, they are not authorized by usb.org, and there is no guarantee that they
are free of conflicts. Still, they are "good enough" for experiments and
hobby projects if you follow the sharing rules: All devices with the same
pair of IDs must use the same driver on kernel level. For details, see the
file USB-IDs-for-free.txt.
